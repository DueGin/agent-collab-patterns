单 Agent 真的最快吗？只在任务小、或强顺序依赖时成立

这次实测里单 Agent 确实最快（24s），但前提有两个：任务小（一份不到 1200 字的方案），它写得也最少（最终答案约 670 字，其它模式约 860–3,060 字）。

耗时主要由关键路径上的串行轮数决定。单 Agent 只有 1 轮；路由、并行分工、投票是 2 轮（27–42s）；辩论、共享黑板是 4 轮（54s）；生成-评审最多 5 轮（99s）；契约编排是 4–6 轮外加代码闸门（208s）。一次调用就能写完的任务，拆分、汇总、评审都只是在加轮数。

任务大、能拆成多个独立且耗时的子任务时，结论反过来：并行扇出的耗时 ≈ 最慢的一路 + 汇总。Anthropic 的 Research 系统用 3–5 个并行子 Agent，复杂查询的调研时间最多缩短约 90%；Kimi K2.5 的 Agent Swarm 在 WideSearch 上达到同等质量的耗时缩短 3–4.5 倍。代价是 token：Anthropic 报告多 Agent 系统约为普通对话的 15 倍。另外，单 Agent 在内部并行调用工具（如 LLMCompiler，最高 3.7 倍）往往已经能拿到大部分提速。

步骤强顺序依赖的任务，拆给多个 Agent 既不快、效果还会变差：Google 等的实验里，所有多 Agent 变体在这类任务上下降了 39–70%。

所以：小任务、强顺序依赖 → 单 Agent 最快也最省；大而可拆分 → 并行扇出（MA-03、MA-04）更快但更贵；加评审、闸门的模式（MA-05、MA-09）是拿时间换质量，几乎总是更慢。

优劣速查

每种模式的完整优劣、适用场景和代表工具，在它自己的页面里。

MA-00单 Agent 基线

＋ 优势

  • 任务一次调用就能完成时，成本和延迟都最低
  • 没有协调开销，没有传话失真
  • 上下文完整，出错时最好排查

－ 劣势

  • 只有一个视角，没有任何自检
  • 错误会直接进入最终结果
  • 任务大且能拆分时没法并行提速，上下文也容易被挤爆

MA-01顺序流水线

＋ 优势

  • 角色分工清晰，每一棒只做一件事
  • 每个环节可以单独替换、单独调优
  • 流程固定，出了问题容易定位是哪一棒

－ 劣势

  • 传话失真：每一棒只看到上一棒的产出
  • 一棒错、棒棒错，没有回头修正的机会
  • 耗时逐棒累加，并行度为零

MA-02路由分诊

＋ 优势

  • 只多一次分类调用，成本几乎和单 Agent 一样
  • 每类问题都交给最合适的专家处理
  • 加一个新领域，只要加一位专家和一个分类

－ 劣势

  • 分错类就全错，而且没有纠正机制
  • 跨领域的问题只能落到一个专家手里
  • 分类器本身成了单点

MA-03并行分工

＋ 优势

  • 几路同时进行，耗时 ≈ 最慢的一路 + 汇总一轮
  • 各路互相看不见，不会被彼此带偏
  • 视角覆盖面可以事先保证

－ 劣势

  • 视角是事先定死的，遇到新问题无法调整
  • 汇总者负担重，容易丢信息
  • 各路之间不能互相纠错，可能重复

MA-04委派式编排

＋ 优势

  • 按任务动态拆分，适应性强
  • 子 Agent 各自用全新上下文并行跑；任务大时能明显缩短耗时
  • Claude Code、Codex、Kimi Code、Hermes 等编码 Agent 都内置了这种做法

－ 劣势

  • 拆分不清就会重复劳动或遗漏
  • 没有验收环节，子任务做错也会被直接汇总
  • 编排者容易成为瓶颈

MA-05生成-评审循环

＋ 优势

  • 质量逐轮提升，有明确的验收标准
  • 评审员更强、上下文干净时提升明显（Codex 写、Claude 审：71.6% → 89.7%）
  • 结构简单，容易加到现有流程上

－ 劣势

  • 标准偏松等于没审，偏严会一直打回、烧钱
  • 每多一轮就多一段串行等待（实测 99s，×8.0）
  • 评审员比写手弱时会帮倒忙（Claude 写、Codex 审：91.4% → 82.8%）
  • 评审员和写手同一家时，错误往往相关，盲点也相同

MA-06多 Agent 辩论

＋ 优势

  • 正反对抗，能逼出反例和隐含假设
  • 裁判看到双方的完整论证再做取舍
  • 正反方用不同模型时，效果普遍更好

－ 劣势

  • 多数基准上并不比单模型 CoT 或多次采样投票更好
  • 容易为了对立而对立
  • 调用次数多，结论质量高度依赖裁判

MA-07投票集成

＋ 优势

  • 多份独立答卷，可以抵消单次失误
  • 有标准答案的题上，多次采样投票通常比辩论更好
  • 答卷可以并行生成，墙钟时间短

－ 劣势

  • 成本约是单次的 N 倍
  • 答卷之间错误相关：越强的模型越容易错成同一个答案
  • 用不同模型混合，平均质量常常不如同一个最强模型多采几次

MA-08团队协作 · 共享黑板

＋ 优势

  • 成员之间能互相看见、互相纠错
  • 讨论过程都留在黑板上，可以追溯
  • 适合多假设并行排查

－ 劣势

  • token 消耗随帖子数增长（实测 ×7.8）
  • 讨论可能发散、收不住
  • 多人写同一处时容易互相覆盖

MA-09契约编排 + 闸门验证

＋ 优势

  • 事前用契约防止重复劳动：写集合不相交，计划用代码校验
  • 有中心协调：Google 等的实验里，错误放大约 4.4 倍，而各自独立并行约 17.2 倍
  • 单写者整合：多个 Agent 贡献内容，只有一个负责写终稿
  • 全程可追溯，附验收对照表

－ 劣势

  • 流程最重，成本最高（实测 ×27.3）
  • 最慢（实测 208s）：评审、返工都是串行的
  • 搭建和维护成本高
  • 简单任务用它很不划算
