优劣速查

每种模式的完整优劣、适用场景和代表工具，在它自己的页面里。

MA-00单 Agent 基线

＋ 优势

  • 成本和延迟都最低，是其它模式的对照组
  • 没有协调开销，没有传话失真
  • 上下文完整，出错时最好排查

－ 劣势

  • 只有一个视角，没有任何自检
  • 错误会直接进入最终结果
  • 任务一长，上下文容易被挤爆

MA-01顺序流水线

＋ 优势

  • 角色分工清晰，每一棒只做一件事
  • 每个环节可以单独替换、单独调优
  • 流程固定，结果可复现

－ 劣势

  • 传话失真：每一棒只看到上一棒的产出
  • 一棒错、棒棒错，没有回头修正的机会
  • 耗时逐棒累加，并行度为零

MA-02路由分诊

＋ 优势

  • 只多一次分类调用，成本几乎和单 Agent 一样
  • 每类问题都交给最合适的专家处理
  • 加一个新领域，只要加一位专家和一个分类

－ 劣势

  • 分错类就全错，而且没有纠正机制
  • 跨领域的问题只能落到一个专家手里
  • 分类器本身成了单点

MA-03并行分工

＋ 优势

  • 多个视角同时进行，墙钟时间约等于最慢的一路
  • 各路互相看不见，不会被彼此带偏
  • 视角覆盖面可以事先保证

－ 劣势

  • 视角是事先定死的，遇到新问题无法调整
  • 汇总者负担重，容易丢信息
  • 各路之间不能互相纠错，可能重复

MA-04委派式编排

＋ 优势

  • 按任务动态拆分，适应性强
  • 子 Agent 各自使用全新上下文，可以并行
  • 编排者掌握全局，是各家编码 Agent 的主流做法

－ 劣势

  • 拆分不清就会重复劳动或遗漏
  • 没有验收环节，子任务做错也会被直接汇总
  • 编排者容易成为瓶颈

MA-05生成-评审循环

＋ 优势

  • 质量逐轮提升，有明确的验收标准
  • 评审员可以换成另一家更强的模型（跨厂商评审）
  • 结构简单，容易加到现有流程上

－ 劣势

  • 标准偏松等于没审，偏严会一直打回、烧钱
  • 轮数越多越慢、越贵（实测 ×8.0）
  • 评审员和写手同源时，盲点也相同

MA-06多 Agent 辩论

＋ 优势

  • 正反对抗，能逼出反例和隐含假设
  • 裁判看到双方的完整论证再做取舍
  • 模型异质时，收益更明显

－ 劣势

  • 容易为了对立而对立
  • 调用次数多，成本较高
  • 结论质量高度依赖裁判

MA-07投票集成

＋ 优势

  • 多份独立答卷，可以抵消单次失误
  • 结果更稳定，不容易离谱
  • 答卷可以并行生成，墙钟时间短

－ 劣势

  • 成本约是单次的 N 倍
  • 同一个模型的答卷容易同质，越强的模型越容易一起错
  • 评委选择或融合的能力决定了上限

MA-08团队协作 · 共享黑板

＋ 优势

  • 成员之间能互相看见、互相纠错
  • 讨论过程都留在黑板上，可以追溯
  • 适合多假设并行排查

－ 劣势

  • token 消耗随帖子数增长（实测 ×7.8）
  • 讨论可能发散、收不住
  • 多人写同一处时容易互相覆盖

MA-09契约编排 + 闸门验证

＋ 优势

  • 事前用契约防止重复劳动：写集合不相交，计划用代码校验
  • 事中隔离执行，事后有规则闸门和独立评审
  • 单写者整合，避免多人同时写终稿
  • 全程可追溯，附验收对照表

－ 劣势

  • 流程最重，成本最高（实测 ×27.3）
  • 最慢（实测 208s）
  • 搭建和维护成本高
  • 简单任务用它很不划算
